The Hooman Loop Design System

Konstrukt

The single source of truth for design tokens across all The Hooman Loop surfaces — web apps, marketing sites, and native iOS. Authored once as JSON, generated into CSS, Swift, and a machine-readable manifest.

Style Bauhaus / Swiss International Palette Atelier Modes Light + Dark

Principles

FlatNo drop shadows. Elevation is communicated with borders and weight, never blur. --shadow: none.
SquareCorners are sharp by default. --radius: 0px.
TypographicSpace Grotesk for display, Inter for body, SF Mono for code. Hierarchy carries the layout.
Restrained colorAn off-white canvas, near-black ink, one teal accent. Feedback, status and category colors are reserved for meaning.
GridA strict 4px spacing scale, --sp-1 through --sp-16.
LegibleEvery text and control pair meets WCAG AA in both modes. npm run check fails the build when one doesn't.

One palette, two modes

Konstrukt ships a single palette, atelier, in light and dark. The mode is an attribute on <html>; use the control in the header to preview it across these docs.

<html data-mode="dark">
AttributeValues
data-modelight · dark (legacy [data-theme="dark"])
data-paletteaccepted, ignored (1.x names hl · sqdl · courage · minimal · blueprint render as atelier)

How it is built

Tokens live as W3C DTCG JSON in tokens/. Primitive color ramps are referenced as {color.teal.700} and resolved at build time; semantic roles link to each other with var(). A Style Dictionary build emits a light and a dark CSS block, a Swift package, the JSON manifest, and the text-layer spec plus Python renderer. npm run check runs the parity gate against the committed snapshot and the WCAG contrast gate. npm run check:text is the text-layer gate.

npm run build       # tokens -> dist/{css,swift,tokens.json,text.json,text.py}
npm run check       # parity vs snapshot + WCAG AA contrast
npm run snapshot    # accept an intended token change
npm run check:text  # linter + golden board
